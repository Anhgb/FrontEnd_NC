LAB 1 · useEffect CƠ BẢN — MOUNT & CLEANUP
⏱ Thời gian: 20 phút     🎯 Mục tiêu: Viết đúng useEffect với mảng phụ thuộc rỗng và hàm dọn dẹp tương ứng
Bước 1 — Tạo file component
Trong thư mục src/features/landmarks/, tạo file mới LuotXemDaiNoi.jsx.
JSX — src/features/landmarks/LuotXemDaiNoi.jsx
import { useState, useEffect } from 'react';
function LuotXemDaiNoi() {
  const [luotXem, setLuotXem] = useState(120);
  // Bước 2 và 3 sẽ được thêm vào đây
  return (
    <div className="the-luot-xem">
      <h3>Đại Nội Huế</h3>
      <p>Đang xem: {luotXem} lượt</p>
    </div>
  );
}
export default LuotXemDaiNoi;
Bước 2 — Thêm useEffect khởi động bộ đếm giờ
Thêm useEffect ngay dưới dòng useState, với setInterval tăng luotXem mỗi giây, và mảng phụ thuộc rỗng để chỉ chạy một lần khi mount.
JSX — bổ sung trong LuotXemDaiNoi
  useEffect(() => {
    console.log('Đã gắn component — bắt đầu đếm lượt xem');
    const idBoDem = setInterval(() => {
      setLuotXem((soCu) => soCu + 1);
    }, 1000);
  }, []);
Bước 3 — Thêm hàm dọn dẹp (cleanup)
Return một hàm huỷ setInterval, kèm console.log để quan sát được thời điểm cleanup chạy.
JSX — hoàn chỉnh useEffect
  useEffect(() => {
    console.log('Đã gắn component — bắt đầu đếm lượt xem');
    const idBoDem = setInterval(() => {
      setLuotXem((soCu) => soCu + 1);
    }, 1000);
    return () => {
      console.log('Dọn dẹp: đã huỷ bộ đếm lượt xem');
      clearInterval(idBoDem);
    };
  }, []);
Bước 4 — Gắn component vào trang để kiểm thử ẩn/hiện
Để quan sát được cleanup chạy đúng lúc unmount, tạm thời thêm một nút bật/tắt trong App.jsx (hoặc trang chi tiết địa danh nếu đã có).
JSX — src/App.jsx  (đoạn kiểm thử tạm thời)
import { useState } from 'react';
import LuotXemDaiNoi from './features/landmarks/LuotXemDaiNoi';
function App() {
  const [hienThi, setHienThi] = useState(true);
  return (
    <div>
      <button onClick={() => setHienThi(!hienThi)}>
        {hienThi ? 'Ẩn thẻ Đại Nội' : 'Hiện thẻ Đại Nội'}
      </button>
      {hienThi && <LuotXemDaiNoi />}
    </div>
  );
}
export default App;

Bước 2 — Tạo hàm mô phỏng gọi API
Vì chưa có máy chủ thật, ta viết một hàm trả về Promise với setTimeout để giả lập độ trễ mạng.
JSX — src/data/fetchMonAn.js
import danhSachMonAn from './mon-an.json';
function fetchMonAn(id) {
  return new Promise((resolve) => {
    setTimeout(() => {
      const monAn = danhSachMonAn.find((m) => m.id === id);
      resolve(monAn);
    }, 800); // giả lập độ trễ mạng 800ms
  });
}
export default fetchMonAn;
Bước 3 — Viết component ChiTietMonAn với useEffect phụ thuộc idMonAn
JSX — src/features/food/ChiTietMonAn.jsx
import { useState, useEffect } from 'react';
import fetchMonAn from '../../data/fetchMonAn';
function ChiTietMonAn({ idMonAn }) {
  const [monAn, setMonAn] = useState(null);
  const [dangTai, setDangTai] = useState(true);
  useEffect(() => {
    let daHuy = false;
    setDangTai(true);
    fetchMonAn(idMonAn).then((data) => {
      if (!daHuy) {
        setMonAn(data);
        setDangTai(false);
      }
    });
    return () => { daHuy = true; };
  }, [idMonAn]);
  if (dangTai) return <p>Đang tải thông tin món ăn…</p>;
  return (
    <div>
      <h3>{monAn.ten} — {monAn.gia.toLocaleString()}đ</h3>
      <p>{monAn.moTa}</p>
    </div>
  );
}
export default ChiTietMonAn;

LAB 3 — Ô TÌM KIẾM TỰ ĐỘNG FOCUS & ĐẾM SỐ LẦN RENDER
LAB 3 · useRef — THAM CHIẾU DOM & GIÁ TRỊ KHÔNG GÂY RENDER
⏱ Thời gian: 20 phút     🎯 Mục tiêu: Dùng useRef đúng cho hai công dụng: tham chiếu DOM và lưu giá trị nội bộ
Bước 1 — Tạo component với ô tìm kiếm tự động focus
JSX — src/features/food/TimMonAn.jsx
import { useRef, useEffect, useState } from 'react';
function TimMonAn() {
  const oTimKiemRef = useRef(null);
  const [tuKhoa, setTuKhoa] = useState('');
  useEffect(() => {
    oTimKiemRef.current.focus();
  }, []);
  return (
    <input
      ref={oTimKiemRef}
      type="text"
      value={tuKhoa}
      onChange={(e) => setTuKhoa(e.target.value)}
      placeholder="Tìm bún bò, cơm hến, bánh bèo…"
    />
  );
}
export default TimMonAn;
Bước 2 — Thêm bộ đếm số lần render bằng useRef
Thêm một ref đếm số lần component render lại, in ra console mỗi lần render để quan sát: giá trị KHÔNG được hiển thị trực tiếp trong JSX (nếu muốn hiển thị, phải dùng useState thay vì useRef — đây chính là điểm cần rút ra ở bước 3).
JSX — bổ sung trong TimMonAn
  const soLanRenderRef = useRef(0);
  soLanRenderRef.current = soLanRenderRef.current + 1;
  console.log('TimMonAn đã render:', soLanRenderRef.current, 'lần');
Bước 3 — Thử nghiệm: hiển thị số lần render lên giao diện
Thêm dòng <p>Đã render {soLanRenderRef.current} lần</p> vào JSX, sau đó gõ vài ký tự vào ô tìm kiếm và quan sát: số hiển thị trên giao diện có tăng theo mỗi ký tự gõ không, so với số in trong console?
JSX — thử nghiệm quan sát (không cần giữ lại sau khi hiểu)
  return (
    <div>
      <input ref={oTimKiemRef} value={tuKhoa}
        onChange={(e) => setTuKhoa(e.target.value)} />
      <p>Đã render {soLanRenderRef.current} lần</p>
    </div>
  );

✅ Điểm cần rút ra
•  Component vẫn render lại đúng số lần bằng với số ký tự gõ vào — vì chính setTuKhoa (useState) là nguyên nhân gây render, không phải soLanRenderRef.
•  soLanRenderRef chỉ đi "ăn theo" số lần render do NGUYÊN NHÂN KHÁC gây ra; bản thân việc gán soLanRenderRef.current không hề kích hoạt thêm bất kỳ lần render nào.

•  Giải thích được bằng lời (nói với bạn cùng nhóm) vì sao thay đổi soLanRenderRef.current không tự nó gây thêm một lần render nào.

Tạo file src/hooks/useDebounce.js. Hook nhận vào (giaTri, doTre) và trả về một giá trị "đã trì hoãn" — chỉ cập nhật sau khi giaTri ngừng thay đổi trong đúng doTre mili-giây.

TÓM TẮT NHỮNG GÌ ĐÃ HỌC TRONG Bài 6
useEffect đồng bộ component với thế giới bên ngoài; mảng phụ thuộc quyết định effect chạy lại khi nào; luôn dọn dẹp (cleanup) những gì effect đã thiết lập.
useRef tạo một hộp chứa giá trị bền qua các lần render mà KHÔNG kích hoạt render lại; dùng để tham chiếu DOM hoặc lưu giá trị nội bộ.
useMemo ghi nhớ KẾT QUẢ của một phép tính tốn kém; useCallback ghi nhớ CHÍNH BẢN THÂN một hàm — chỉ dùng khi đã xác định thật sự cần thiết.
Custom Hook đóng gói logic có trạng thái để tái sử dụng nhiều nơi, luôn đặt tên bắt đầu bằng use.
Hook chỉ được gọi ở cấp cao nhất của component hoặc Custom Hook, không trong vòng lặp/điều kiện.
